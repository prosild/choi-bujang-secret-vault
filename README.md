### 1. GitHub 최신 커밋과 파일 확인

저장소를 로컬에 내려받은 뒤 다음 명령을 실행합니다. `origin/main`을 명시하여 작업 폴더의 미커밋 변경과 구별합니다.

```bash
git fetch origin main
git rev-parse origin/main
git ls-tree -r --name-only origin/main | grep -E '(^|/)data\.json$' || true
git grep -n -F -e '실습용 가상 과제 기록' -e '실습용 가상 포트폴리오 기록' -e '실습용 가상 리추얼 기록' -e '실습용 가상 행정 기록' origin/main -- . ':!README.md' || true
```

기대 결과는 `data.json`, `public/data.json` 경로가 없으며 네 문장에 대한 일치 결과도 **0건**인 것입니다. 이 README에는 검색 패턴 자체가 포함되므로 `README.md`는 검색에서 제외합니다. 다른 파일에 같은 문장이 나오면 해당 파일의 위치를 기록하고 공개 여부를 재검토합니다. `git grep`의 일치 결과가 전혀 없다는 사실과 실제 검사를 실행했다는 사실을 구분하여 기록합니다.

### 2. 현재 배포의 비로그인 정적 응답 확인

현재 Vercel Production 배포 URL에서 로그아웃하거나 시크릿 창을 사용하여 다음 경로를 열어 봅니다.

| 요청 경로 | 정상 기대 결과 | 검사 항목 |
| --- | --- | --- |
| `/` | 200, 카드 4건(서버 API 로드 후) | 초기 HTML 응답에 가상 메모 본문이 직접 포함되지 않음 |
| `/data.json` | 404 등 또는 메모 본문이 없는 응답 | 예전 가상 메모 문장 0건 |
| `/aleph.json` | 200, 배포 식별 JSON | `repoUrl`과 `commit`이 GitHub 최신 커밋과 일치하고 메모 본문은 없음 |
| `/api/notes` | 현재 200, 가상 메모 4건 | **비로그인 읽기가 가능하다는 약점을 별도로 기록** |

브라우저 개발자 도구의 Network 탭에서 각각의 **응답 본문**을 확인합니다. 페이지 화면의 네 카드는 `/api/notes` 호출 후 표시되는 것이므로, 렌더링된 화면과 `/`의 최초 HTML 응답을 혼동하지 않습니다. `/aleph.json`의 `commit`을 앞서 확인한 `git rev-parse origin/main` 값과 비교하되, 새 커밋과 배포 시점 차이가 있다면 실제 배포 커밋을 따로 기록합니다. 비밀키나 메모 본문은 기록하지 않습니다.

### 4. 현재 남은 보호 한계

- `public/data.json`이 제거되고 Supabase의 `anon`·`authenticated` 테이블 읽기 권한이 없어도, **Vercel의 `/api/notes`는 서버 전용 키로 조회한 제목·본문을 비로그인 요청에 응답**합니다. 정적 파일 제거와 실제 접근 제어는 다른 문제입니다.
